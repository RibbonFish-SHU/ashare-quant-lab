# 日期粒度公告的可见时间诊断

主代理，2026-10-04。已批准本工程批次；不需要新增数据权限、网络采集、环境或服务器任务。

## 目的与决定

既有官方公告可核实到发布日期，但网页日期标签不等于当日零点已公开。
当前抓取时间也不能代替历史发布时间。增加独立、可测试的诊断层，量化在显式保守假设下，
某份公告版本最早能用于哪个信号时点；不修改原始候选的 `available_time=null` 或研究资格。

本批只实现日期粒度的假设和当前捕获视图，不生成“已认证历史时间”的新通道。
API 不接受事件生效日作为发布时间替代值，也不从代码、文件名时间、PDF 制作时间或账户时钟推断发布时间。

## 接口行为

- 输入显式的证据 ID、来源摘要、公告日期（可未知）、带时区的实际观察时间（可未知）、
  可选的来源明确版本日期、原件落款日期和显式日期矛盾标记。
  只有来源明确表达的版本日期可用，任意文件系统 mtime 不能充当来源版本日期。
- `date_upper_bound` 诊断采用 `max(公告日期, 已知版本日期)` 后一上海自然日零点；
  输出名称明确带有 scenario / assumption，不伪称精确历史可用时间。
  周末和节假日不自动移到交易日；策略信号由调用方另接显式交易日历。
- 落款早于发布日期是合法的隔夜披露；落款晚于发布日期、显式日期矛盾、
  没有公告日期等情形不得静默产生日期假设。已知后续版本不回溯为原公告日可见。
- `observed_at` 视图仅从实际抓取完成之后可见，保留这个时间代表当前捕获的意义。
  缺少观察时间不能填当前系统时钟。日期晚于实际观察的上海日期是矛盾，明确拒绝或记录不可用原因。
- 所有时间查询要求带时区，归一化后使用包含端点的 `<= knowledge_time`；
  不依赖本地系统时区。仅有日期标签的 epoch 零点值不得作为精确秒级时间使用。
- 输出保留证据 ID、摘要、原值、模式、假设时点和未核实的历史修订风险。
  `available_time` 保持 null，`research_eligible=false`。
  日期矛盾可以阻止历史假设视图，但不能抹去后来确已抓到原件的观察事实。
