## 已集成的行为

日期情景采用 `max(公告日期, 显式来源版本 / 附件下界日期)` 后一上海自然日零点，
捕获视图仅从有凭据的实际抓取完成时刻开始。两视图不互相补值；周末不自动推进到交易日。
未知时间返回未知，已知时间使用包含端点的比较。落款早于披露可以合法，晚于披露或明确矛盾
会阻止日期情景，但不会抹去后来确已捕获的事实。接口及限制见
[PUBLICATION_TIMING_CONTRACT.md](PUBLICATION_TIMING_CONTRACT.md)。

模块不读取文件、网络、时钟或真实候选，不生成已认证历史可用时间。
附件 `createAt` 仅作为明确命名的情景下界，不能解释成已认证的历史版本发布时间。

## 真实原件的诊断结果

主代理绑定 3 个成员调整、7 份分红公告（6 份实施、1 份预案）、6 份停复牌公告及
1 个晚创建附件，共 **17 个案例**。离线审计前后核对 **50 个不同输入引用**，源码工作区干净，
4 个模块 / 测试 / 契约文件未变化，审计耗时 **0.094 秒**。

| 日期情景结果 | 数量 | 含义 |
| --- | ---: | --- |
| 不晚于所选比较时点 | 11 | 仅在显式假设下满足时间比较，不解除来源及修订风险 |
| 晚于所选比较时点 | 4 | 三份同日复牌公告及一份晚创建附件 |

  次日零点情景分别为 2023-06-27、02-18、06-28，均晚于各自复牌日 09:30 开盘。
  不能把事件生效时刻倒填为发布时间。
- `csi-14599-attachment` 的公告日期为 02-03，官方 API 所报附件创建日期为 03-16；
  显式下界情景为 **03-17 零点**，不能回填为 02-04。
- `1217071606` 公告标签为 2023-06-15，原文落款为 2022-06-15，原有明确冲突标记保留，
  日期情景不可用。不能因通常允许“落款早于披露”而忽略已核实的年份矛盾。
- 13 份 CNINFO 原件有 2026 年的抓取完成记录，捕获视图只在该时刻及之后可见。
  3 个 CSI 成员案例与晚附件缺少可靠的完成时间，观察视图保持未知；没有使用请求开始时间、
  文件 mtime 或当前时钟代填。

审计还逐例核对了日期情景端点前 1 微秒及端点、已知捕获完成端点，以及固定研究门禁。
案例输入保留所有旧标签；宁德时代旧 `timestamp_label_unverified` 显式映射到模块的
`minute_label_unverified`，只使用上海公告日期，不将时分秒标签升级为精确历史发布时间。

## 验证、修复与证据

新模块专测 **83 passed in 0.12s**，Ruff check 与三份 Python 文件格式检查通过。
主审发现最大 UTC 观察时刻转换为上海日期会泄露原生 `OverflowError`；修复后两视图都明确抛出
`PublicationTimingError`，新增测试覆盖该路径。原始复现及最终检查日志保留，未重复旧模型、账本 smoke
或已有效的全量测试。集成文件与已验证提交仅按 CRLF/LF 归一化比较，内容一致。

真实案例审计首次因未覆盖旧 `timestamp_label_unverified` 标签而断言失败，未写成功结果。
主代理保留首次脚本并写明回顾性失败记录；当次完整 stdout/stderr 和准确开始时间未保存，
不补造原始日志。修正显式标签映射后上述 17 例审计通过，没有修改业务模块或原始配置。
