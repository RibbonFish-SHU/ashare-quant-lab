# 数据来源评估与时间划分草案

维护者：主代理。核实日期：2026-10-03。
状态：公开文档与 SDK 接口已核实；真实数据源、账户权限及历史覆盖未确定，
尚未运行批量数据获取或模型评估。本文为 Phase 0 的选源准备，不是数据验收报告。

## 当前决定

- Phase 0 先实现与供应商无关的数据契约和明确标注的 synthetic 工程样例。
- 优先使用用户已有且有权使用的数据。没有现成来源时，先验证公开 / 免费候选的小样本，
  再评估是否需要用户已有的 Tushare Pro 等服务。当前不购买数据、不假定账户权限。
- 数据来源至少需要满足历史股票池、未复权行情、复权依据、交易日历、上市 / 退市、
  ST / 停牌 / 涨跌停，以及来源和可用时点记录。单一接口存在不能证明全部条件已满足。
- 历史成分月度快照不能直接等同于逐日准确成员；当前成分和当前上市名单不能反推历史。

## 真实数据接入前的核实

1. 对不同历史年份和实际成分调整前后日期做小样本查询，保存原始返回、查询参数、
   获取时间、版本和校验摘要，核对生效日期与公告 / 数据可用时间。
2. 从独立官方公告或可靠第二来源核对成员变化。若仅有月度快照，不把月末成员
   向月初回填；无充分变更依据时标记股票池未验收，而不是悄悄改变为当前成分回测。
3. 核对除权除息、停牌、复牌、ST 变更、上市和退市样本，以及行情缺失与真实休市的区别。
4. 分清 `event_date`、`effective_date`、`publish_time`、`available_time` 和实际
   `ingested_at`。当前下载记录只能直接证明此次观察，不能伪装成历史发布时间。
5. 数据质量核实不运行策略、不比较收益、不据模型结果筛选历史年份。
   若需读取拟封存区间做质量检查，应预先限定字段 / 检查和可见输出，保留记录，
   不向研究代理暴露标签分布、模型得分或表现；当前未读取封存区间数据。

## 时间划分草案（未冻结）

以下是覆盖足够时的候选设计，不代表供应商已覆盖该区间，也不启动实验。

- 候选历史数据范围：2010–2025 年；特征预热须额外保留实际所需历史。
- 开发期 Walk-Forward：5 年训练 + 1 年验证 + 6 个月样本外评估，按 6 个月滚动；
  最早评估段为 2016 年上半年，开发评估最多使用到 2023 年末。
- 候选最终封存区间：2024–2025 年。其训练 / 再训练日程、是否按固定日历滚动、
  允许使用的已成熟标签和输出权限，应在任何策略结果可见前单独冻结。
- 2026 年若有数据，可作为后续前向 / 模拟运行候选，不用来临时选择有利回测区间。
- 开发期样本外评估若反复参与模型选择，只能称开发证据，不能冒充最终盲测。
- 按标签真实起止和可用时点处理跨边界样本；划分边界处的模型与预处理只使用
  当时允许且已成熟的数据。不能因存在固定“五日预测”就不检查实际交易日跨度。
- 如果历史成员、状态或行情覆盖不足，先报告实际可用区间，再在未见模型结果的条件下
  调整草案；不通过混用不同时点的股票池凑齐 2010 年以来的数据。

用户的数据来源、已有权限及期望历史区间仍待答复；研究时间边界确认后应形成明确冻结记录，
而不是让各模型在运行时自行挑选。
