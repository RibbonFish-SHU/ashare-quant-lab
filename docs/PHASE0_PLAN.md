# 首轮任务：Phase 0 基础设施与数据契约准备

日期：2026-10-03。方案：[PROJECT_PLAN.md](../PROJECT_PLAN.md)。
用户已要求由主代理协调一个 Herdr 实验代理开始工作。当前任务书把方案首轮实施拆成
可交付批次；后续阶段依照用户方案及其验收顺序推进。

## 本轮目标

建立可安装、可配置、可记录版本的研究基础，以及能检查数据时点和结构的数据入口。
完成本轮后应能明确：环境是否兼容、研究流程是否能运行、真实数据还有哪些缺口。
不以合成数据 smoke 代替 Phase 0 的真实数据读取验收或后续正式回测。

## 执行顺序与产物

1. **环境与依赖**：检查项目 Git 状态和相关服务器资源，确定兼容的 Python 版本；
   建立独立环境、项目元数据和明确版本的依赖。验证 Qlib、LightGBM、PyTorch、
   Arrow / Parquet 和 DuckDB 的安装及最小实际调用，记录平台差异和失败。
2. **最小研究入口**：实现配置读取、结构化日志、固定随机种子、独立运行目录及
   版本清单；至少提供一条可复现的检查 / smoke 命令。配置错误应给出具体原因。
3. **数据契约与存储**：定义并验证行情、交易日历、历史成分变更、复权 / 公司行为、
   股票状态及来源时间字段。实现 Parquet 写读与 DuckDB 查询的小型闭环，
   检查重复主键、日期 / 时区、必需字段和数据可用时点。
4. **隔离的工程样例**：在明确标记 synthetic 的小样本上验证读写与时间边界，
   包括成分生效变更、晚到 / 修订数据、未来可用数据拒绝等代表性情形。
   不产生或宣传策略收益结论，不将样例与真实数据混存。
5. **设备检查与单卡 smoke**：在授权服务器上确认设备数量和型号，仅选择即时核实
   空闲的设备做最小训练验证，记录设备、版本、日志和退出状态。可通过设备枚举
   与选择接口验证调度能力，不能为验收占用其他项目正在使用的 GPU。
   没有 Slurm / PBS 命令不等于没有预约；预约或容量条件不满足时保留未完成验收项，
   继续本地工作，不以占用共享资源来完成检查。
6. **数据来源评估**：依据用户回复或可用公开资料核实历史日线、历史沪深 300 成分、
   复权、ST / 停牌 / 涨跌停及交易日历的覆盖与获取条件，记录缺失和授权条件。
   不购买数据或将无法核实的接口当成已验证数据源。
7. **完成交接**：记录实际命令、环境 / 版本、测试范围、运行产物、失败及未完成验收。
   完成可独立交付的批次，交主代理审阅；数据源未确定也不阻断前述独立工程工作。

## 数据与时序设计要求

- 数据至少有明确标识、交易日 / 事件日、来源和版本；公告类 / 修订类数据保存
  publish_time、available_time 等可验证时间语义，统一说明 Asia/Shanghai 与存储时区。
- 保留原始价与复权来源 / 版本。不能直接用最新全历史复权结果假装每个历史时点已知。
- 股票池保存历史成员生效区间及可用信息，不能从当前成分推导历史，也不能忽略退市股票。
- 收盘后信号只能使用截至该时点已可获得的特征；next-open 等成交价属于后续执行信息。
- 5 日标签需要明确起止成交时点、交易日索引、复权口径、超额收益参照和成熟时间。
  先写出明确的小时间轴并测试错位边界，再据此实现训练 / 回测，不把 T 日收盘价
  同时用作收盘后信号的可成交价格。
- Walk-Forward 使用时间划分，变换 / 标准化在训练范围拟合；按真实标签区间处理
  跨边界重叠和标签可用性，不能只删除一个固定天数而不核对实际跨度。
- 交易费用和股票交易规则采用可追溯、可配置的时间口径；不把临时假设冒充实际券商费率。

## 验收与本轮边界

- 安装、配置 / 日志入口、Parquet / DuckDB 闭环与代表性数据时点检查有真实运行证据。
- 单卡训练验证和设备选择记录可追溯；没有空闲资源时明确保留这一未完成项。
- 真实数据完整读取依赖选定数据源，未完成时不能宣称整个 Phase 0 已验收。
- 本轮不开展大规模调参、复杂模型、自动 Alpha 搜索或最终封存测试，不接入实盘。
  对后续阶段的设计可作准备，但结果不得跨过方案对应的验收前提。
